Simplified ARM-like instruction set
32 bit Instructions (fixed width, 4 bytes, little endian)
32 register slots
	- x0, x1, ..., x29 (30 general purpose registers)
	- SP (register 30), XZR (register 31, always reads as 0, writes are discarded)
	- PC (not addressable, starts at 0 after reset)
	- PSTATE (see below)
	- FPCR https://developer.arm.com/documentation/100446/0100/aarch64-register-descriptions/fpcr--floating-point-control-register
	- FPSR https://developer.arm.com/documentation/100446/0100/aarch64-register-descriptions/fpsr--floating-point-status-register
	  (FPCR and FPSR are not implemented yet, they are only TODOs in the emulator)

Register conventions
	- x0-x7: parameter registers (the swi handler only reads x0-x5)
	- x0: return value
	- x8: syscall number
	- x0-x17: caller saved
	- x19-x27: callee saved
	- x28: frame pointer (FP)
	- x29: link register (LR), written by BL/BLX
	- Stack grows downwards

PSTATE (reset value is 0)
	- bit 0: N (negative)
	- bit 1: Z (zero)
	- bit 2: C (carry)
	- bit 3: V (overflow)
	- bit 8: user mode flag (reserved, unused)
	- bit 9: real memory mode flag (reserved, unused)
	- Only NZCV are used right now. MSR/MRS (the only way to access PSTATE as a system register)
	  are not implemented yet.

Carry flag convention
	- Addition (ADD, ADC, CMN): C is the carry out
	- Subtraction (SUB, RSB, SBC, RSC, CMP): ARM convention, C = NO borrow (C=1 when op1 >= op2).
	  This is consistent with the HI/LS/HS/LO condition codes.

INSTRUCTION SET ARCHITECTURE
	- Attempted to make these instruction encodings be as realistic as possible
	(keep specific register encoding locations constant)
	- Bit 25 is the "update flags" (S) bit for the formats that have one
	- Opcode is bits 26-31. Opcode 000000 is the 'special' instruction group (see below).
	  Opcodes that are not assigned (see AVAILABLE OPCODES) dispatch to HLT.

O Type Instruction
----------------------------------------------------------------
OP{S} xd, xn, arg
000000 | 0 | 00000 | 00000 | 1 | 00000000000000
opcode	 S    xd      xn   ?imm       imm14
000000 | 0 | 00000 | 00000 | 0 | 00000 | 00 | 00000 | 00
opcode   S    xd      xn   ?imm   xm    shift  imm5   --

O1 Type Instruction
OP xd, xn, [imm5 | xm]
000000 | 0 | 00000 | 00000 | 0 | 00000 | 00 | 00000 | 00
opcode   S     xd      xn  ?imm    xm    --    imm5   --
	- ?imm is bit 14. If set, the shift amount is imm5 (bits 2-6), otherwise it is the low 8 bits of xm
	- If S is set, N and Z are set from the result, C from the last bit shifted out (ARM behavior)
	  and V is unchanged. A shift amount of 0 leaves C unchanged.

O2 Type Instruction
OP{S} xlo, xhi, xn, xm
000000 | 0 | 00000 | 00000 | 0 | 00000 | 00000 | 0000
opcode   S    xlo     xhi    -    xn      xm     ----

O3 Type Instruction
OP{S} xd, arg
000000 | 0 | 00000 | 1 | 0000000000000000000
opcode   S    xd   ?imm         imm19
	- xd = imm19 (zero extended)

000000 | 0 | 00000 | 0 | 00000 | 00000000000000
opcode   S    xd   ?imm   xn          imm14
	- xd = xn + imm14 (the immediate is added to the register)

?imm for O3 is bit 19.

M Type Instruction
----------------------------------------------------------------
adr
00: simple/offset
01: preindexed
10: postindexed

000000 | 0 | 00000 | 00000 | 0 | 00000 | 00 | 00000 | 00
opcode ?sign   xt      xn  ?simm  xm    shift  imm5  adr

000000 | 0 | 00000 | 00000 | 1 | 000000000000 | 00
opcode ?sign   xt      xn  ?simm   simm12      adr
	- ?simm is bit 14, simm12 is bits 2-13 and is sign extended by the emulator
	- ?sign (bit 25) makes LDRB/LDRH sign extend the loaded value (LDRSB/LDRSH).
	  It has no effect on LDR. For STRB/STRH it sign extends the register value before it is truncated,
	  which does not change the stored bytes.

M1 Type Instruction
000000 | 1 | 00000 | 00000000000000000000
opcode ?sign   xd            imm20
	- ?sign (bit 25) is set by the loader/linker when the page offset to the target is negative
	  (bit 20 of the 21 bit page offset), imm20 holds the lower 20 bits of the page offset

BX{CD} xd

Miscellaneous Instructions (special group, opcode 000000)
000000 | 0000 | 0000000000000000000000
opcode  ext. op         imm22

The extended op is bits 22-25. An unknown extended op throws a BAD_INSTR exception.

000000 | 0000: HLT
    - 000000 | 0000 | 0000000000000000000000
	- Stops program execution. The encoding is 0x00000000, so running into zeroed memory halts.

000000 | 1111: NOP
	- 000000 | 1111 | 0000000000000000000000
    - Does nothing

000000 | 0001 : MSR sysreg, xn|imm16
    - 000000 | 0001 | 00000 | 0 | 00000 | 00000000000
                     sysreg  ?imm  xn
    - 000000 | 0001 | 00000 | 1 | 0000000000000000
                     sysreg  ?imm     imm16
    - Move to system register
    - NOT IMPLEMENTED: always throws a BAD_REG exception ("System register N unimplemented")

000000 | 0010: MRS xn, sysreg
	- 000000 | 0010 | 00000 | 0 | 00000 | 00000000000
                       xn            sysreg
    - Move from system register
    - NOT IMPLEMENTED: always throws a BAD_INSTR exception ("MRS unimplemented")

000000 | 0011: TLBI flags(, xt)
    - 000000 | 0011 | 00000 | 0 | 0000000000000000
                        xt   ?xt    imm16, specify TLBI operation
    - Flush the TLB, flags to specify how to do so
    - NOT IMPLEMENTED: always throws a BAD_INSTR exception ("TLBI unimplemented")

000000 | 0100: Atomic Operations
    000000 | 0100 | 00000 | 0 | 00000 | 00000 | 00 | 0000
                     xt     -    xn      xm    width atop
    - width: 00 = word, 01 = byte (B), 10 = half-word (H)
    - atop (bits 0-3) selects the operation below. The width bits (4-5) select the access size.
    - SWP{B|H} xt, xn, [xm]
	    - Writes the value at the address xm to xt, storing xn into address xm
	    - atop 0000

    000000 | 0100 | 00000 | 0 | 00000 | 00000 | 00 | 0001
                     xt     -    xn      xm    width atop
    - LDADD{B|H} xt, xn, [xm]
        - Writes the value at address xm to xt, adding xn into address xm

    000000 | 0100 | 00000 | 0 | 00000 | 00000 | 00 | 0010
                     xt     -    xn      xm    width atop
    - LDCLR{B|H} xt, xn, [xm]
        - Writes the value at address xm to xt, clearing the bits specified by xn at address xm

    000000 | 0100 | 00000 | 0 | 00000 | 00000 | 00 | 0011
                     xt     -    xn      xm    width atop
    - LDSET{B|H} xt, xn, [xm]
        - Writes the value at address xm to xt, setting the bits specified by xn at address xm



Arithmetic Instructions (9)
000001: ADD{S} xd, xn, arg (O)
	- adds xn and arg and stores in xd
	- {S} specifies whether the NZCV flags are updated as a result of the operation

000010: SUB{S} xd, xn, arg (O)
	- subtracts arg from xn and stores in xd

000011: RSB{S} xd, xn, arg (O)
	- subtracts xn from arg and stores in xd

000100: ADC{S} xd, xn, arg (O)
	- adds xn and arg with the current state's carry flag and stores in xd

000101: SBC{S} xd, xn, arg (O)
	- subtracts arg from xn, and the inverse of the current state's carry flag (borrow), and stores in xd

000110: RSC{S} xd, xn, arg (O)
	- subtracts xn from arg, and the inverse of the current state's carry flag (borrow), and stores in xd

000111: MUL{S} xd, xn, arg (O)
	- multiplies xn and arg and stores the lower 32 bits in xd
	- {S} updates N and Z, C and V are left unchanged

001000: UMULL{S} xlo, xhi, xn, xm (O2)
	- multiplies unsigned xn and xm and stores the result into {xhi, xlo}
	- {S} updates N (bit 63 of the result) and Z (64 bit result is 0), C and V are left unchanged

001001: SMULL{S} xlo, xhi, xn, xm (O2)
	- multiplies signed xn and xm and stores the result into {xhi, xlo}
	- flags are updated like UMULL

Bitwise Instructions (8)
010110: AND{S} xd, xn, arg (O)
010111: ORR{S} xd, xn, arg (O)
011000: EOR{S} xd, xn, arg (O)
011001: BIC{S} xd, xn, arg (O)
	- {S} updates N and Z, C and V are left unchanged
011010: LSL{S} xd, xn, {xm|#imm5} (O1)
011011: LSR{S} xd, xn, {xm|#imm5} (O1)
011100: ASR{S} xd, xn, {xm|#imm5} (O1)
011101: ROR{S} xd, xn, {xm|#imm5} (O1)
	- {S} updates N and Z from the result and C with the last bit shifted out, V is unchanged.
	  A shift of 0 leaves C unchanged. LSL/LSR by 32 or more give 0 (ASR gives the sign fill),
	  ROR rotates by the amount modulo 32 and C is bit 31 of the result.

Comparison Instructions (4)
	- Always update the NZCV flags, there is no destination register (the assembler injects xzr as xd)
011110: CMP xn, arg (O)   (like SUBS)
011111: CMN xn, arg (O)   (like ADDS)
100000: TST xn, arg (O)   (like ANDS)
100001: TEQ xn, arg (O)   (like EORS)

Data Movement Instructions (2)
100010: MOV{S} xd, arg (O3)
100011: MVN{S} xd, arg (O3)
	- {S} updates N and Z, C and V are left unchanged

Memory Access Instructions (6 opcodes)
100100: LDR{B|H} xt, mem (M)
	- op: 100100 (Word), 100101 (Byte), 100110 (Half-Word)
	- LDRSB/LDRSH (sign extend) are LDRB/LDRH with the ?sign bit set
100111: STR{B|H} xt, mem (M)
	- op: 100111 (Word), 101000 (Byte), 101001 (Half-Word)

Branching Instructions (5)
101101: B{CD} simm22 (B1)
101110: BL{CD} simm22 (B1)
	- stores the address of the next instruction in x29 (LR)
101111: BX{CD} xd (B2)
	- BX X29 equivalent to ret
110000: BLX{CD} xd (B2)
	- stores the address of the next instruction in x29 (LR)
110001: SWI{CD} - (B1)
	- operation depends on the value of register x8 which gives the syscall identifier
	- operation, if returning anything, writes to x0
	- registers x0 through x5 can be used as arguments
	- implemented syscalls (emulator specific):
		1000: emu_print                         prints the emulator state
		1001: emu_printr   reg_id               prints a register
		1002: emu_printm   addr, size, little_endian   prints a value in memory
		1003: emu_printp                        prints PSTATE
		1010: emu_assertr  reg_id, min, max     fails (FAILED_ASSERT exception) if the register is outside [min, max]
		1011: emu_assertm  addr, size, little_endian, min, max   same for a memory value
		1012: emu_assertp  pstate_bit, expected   same for a PSTATE bit
	- any other syscall number throws a BAD_INSTR exception ("Invalid syscall number N")
	  (emu_log 1020 and emu_err 1021 exist as helpers but are not dispatched yet)

Addressing Instructions (1)
110010: ADRP xd, symbol (M1)
	- xd = (pc & ~0xFFF) + page offset, where the page offset is simm21 pages computed by the loader
	  from the relocation (:hi20:). The assembler syntax is adrp xd, sym, and then
	  add xd, xd, :lo12:sym to get the full address.
